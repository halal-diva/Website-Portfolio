Where a Contact Form Submission Actually Goes

A plain-language walkthrough of what happens after someone hits "Send message" on my site — written so I can explain it to anyone who asks, without hand-waving.

The short version

My website is just files — HTML, CSS, a bit of JavaScript. It has no server of its own, so it has no way to send an email by itself. Instead, the form hands the message off to Netlify, the same company already hosting the site, and Netlify does the actual delivering.

One-line answer

"There's no backend I built myself — the form submits to Netlify, who I'm already hosting the site through, and they forward it to my email."

The journey, step by step

You type a message and hit Send

The browser first checks the message locally — is a field empty, does the email look real? This happens instantly, before anything leaves your device, so obvious mistakes get caught right away.

The submission travels to Netlify's servers

Once it passes those checks, the browser sends the name, email, and message to Netlify — not to me directly, and not to any server I wrote or manage.

Netlify stores it

Every submission is logged in my Netlify dashboard, so there's always a record I can look back on, even before checking email.

Netlify sends me an email

Because I turned on an email notification for this form, Netlify's own mail system automatically forwards the details to my inbox — I never had to write or host any code that sends email.

The sender sees a confirmation

Meanwhile, back on the site, they see a friendly "Thanks — I'll be in touch soon" message, so they know it actually went somewhere instead of wondering if it worked.

Why this counts as "no server needed"

Normally, handling a form submission and sending an email requires writing backend code — something that runs on a server, waits for form data, and calls an email service. I didn't build or pay for any of that. Netlify already provides it as part of hosting the site, triggered just by two small attributes in my HTML (data-netlify="true" and a matching form name). That's the whole trick: I'm borrowing infrastructure that already exists instead of building my own.

What the JavaScript adds on top

The delivery mechanism above happens either way. The JavaScript I added doesn't change where the message goes — it just makes the moment around sending it feel better:

Without the JS layer

Submitting reloads the whole page and dumps you on a generic Netlify success page — no feedback if you forgot a field, easy to bounce off confused.

With the JS layer

Empty fields or a bad email get caught instantly with a clear message, right on the page. A real send shows a warm confirmation without ever leaving the site.

In short: Netlify is the delivery system, and the script is just good manners layered on top of it.
